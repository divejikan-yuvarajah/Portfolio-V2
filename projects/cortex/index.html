01 · CONTEXT

The problem

The project repository describes teams moving between separate inventory, CRM, finance and operations tools to answer routine business questions. CORTEX proposes a shared operating system for those workflows.

Project goals

  • Bring business records and operational areas into a shared workspace.
  • Support natural-language questions and actions across business modules.
  • Keep workflows, analytics and knowledge features within one application.

MY ROLE

Contribution boundary

CORTEX is represented by a public repository owned by collaborator Abdul Basith and a team preview. The materials available for this audit do not assign specific modules to me, so this case study describes the documented team system without claiming individual feature ownership.

03 · TECHNICAL VIEW

Architecture & implementation

The collaborator-owned README describes a Next.js App Router application with API routes, PostgreSQL/Supabase, Prisma, optional Redis/BullMQ workers and external LLM providers. These are repository-listed components; my personal implementation contribution is not established by that source.

  • A browser client uses the Next.js application and its API routes.
  • The API layer is documented as coordinating tenant-scoped application data and authentication.
  • PostgreSQL/Supabase is paired with Prisma; pgvector is listed for vector storage.
  • Optional background workers use Redis/BullMQ, while AI calls use a configured external provider.
  • Next.js 16 (README-listed)
  • TypeScript 5 (README-listed)
  • PostgreSQL / Supabase
  • Prisma 6
  • pgvector
  • Redis / BullMQ (optional)

The stack and architecture are taken from a public collaborator repository README, not independently checked against the repository's source files in this audit.
